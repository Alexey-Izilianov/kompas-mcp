## 1. Назначение программы

kompas-mcp — сервер протокола MCP (Model Context Protocol) для КОМПАС-3D v22.
Он даёт языковой модели (Claude Code, Claude Desktop и другим MCP-клиентам)
набор инструментов, которыми модель по запросу на обычном языке строит
документы в КОМПАСе.

**Функции программы:**
- чертежи по ЕСКД: виды, примитивы, размеры, штриховка, шероховатость, линии
  разреза, технические требования, основная надпись; экспорт в PNG и DXF;
- готовые чертежи деталей передач: цилиндрическое и коническое колесо,
  червяк, червячное колесо, пружина сжатия — с таблицей параметров;
- 3D-детали из эскизов: выдавливание, вращение, вырезы, отверстия, фаски,
  скругления; материал, масса, рендер в PNG;
- 3D-модели передач и их сборки в зацеплении: цилиндрической, конической,
  червячной;
- пружины сжатия и растяжения (3D);
- стандартные изделия по таблицам ГОСТ: болты, гайки, шайбы, шпильки,
  штифты, шарикоподшипники;
- сборки: вставка и расстановка компонентов; сборочный чертёж с позициями
  и спецификация по ГОСТ 2.106;
- расчёты без КОМПАСа: геометрия передач, допуски и посадки, моменты
  инерции сечений, справочник материалов; проверочные расчёты передач и
  пружин со строками для технических требований;
- копилот «Давинчи» — окно чата в КОМПАСе пользователя.

**Ограничения:**
- в 3D эвольвентный профиль зуба — только у цилиндрических колёс, у
  конических и червячных профиль прямобочный 20°;
- резьба не моделируется, крепёж строится по номинальному диаметру;
- спецификация — один лист А4, до 25 строк;
- проверочные расчёты упрощены и подходят для эскизного проектирования;
- программа проверена на КОМПАС-3D v22.

## 2. Условия выполнения программы

**Аппаратные средства** — те же, что для КОМПАС-3D v22.

**Программные средства:**
- Windows 10 или Windows 11, 64-разрядная;
- КОМПАС-3D v22 с SDK (папка `SDK` входит в стандартную установку);
- .NET Framework 4.8;
- для формирования interop-сборок — TlbImp из Windows SDK (компонент
  «.NET Framework 4.8 SDK»); вместо этого можно взять готовые interop-DLL
  из SDK КОМПАС;
- MCP-клиент: Claude Code, Claude Desktop или другой, поддерживающий stdio;
- для копилота «Давинчи» — Claude Code (`claude`), в котором выполнен вход.

**Квалификация оператора:** знание ЕСКД и работы в КОМПАС-3D на уровне
конструктора; навыки работы с MCP-клиентом.

## 3. Выполнение программы

### 3.1 Установка

1. Распакуйте `kompas-mcp-1.0.0-win64.zip` в любую папку. Права
   администратора не нужны.
2. Сформируйте interop-сборки КОМПАСа (в архив они не входят — лицензия
   ASCON не разрешает их распространять):
   ```
   powershell -ExecutionPolicy Bypass -File interop.ps1
   ```
   Скрипт находит КОМПАС по реестру, берёт библиотеки типов из
   `<КОМПАС>\SDK\lib` и кладёт DLL рядом с `KompasMcp.exe` и в папку
   `davinci`. Если TlbImp не найден, скопируйте вручную из SDK КОМПАС
   `Kompas6API5.dll`, `KompasAPI7.dll`, `Kompas6Constants.dll`,
   `Kompas6Constants3D.dll` рядом с `KompasMcp.exe` (и `KompasLibrary.dll`
   в `davinci`).
3. Проверьте сервер: `KompasMcp.exe --version` выводит `kompas-mcp 1.0.0`.

Если КОМПАС ни разу не запускался после установки, запустите его один раз
вручную: при первом запуске он регистрирует свои COM-классы.

### 3.2 Подключение к MCP-клиенту

**Claude Code:**
```
claude mcp add kompas -- C:/путь/KompasMcp.exe
claude mcp list
```
Путь пишется прямыми слэшами. `claude mcp list` должен показать
`kompas: ... ✔ Connected`.

**Claude Desktop** — добавьте в `claude_desktop_config.json` и перезапустите
приложение:
```json
{
  "mcpServers": {
    "kompas": { "command": "C:\\путь\\KompasMcp.exe" }
  }
}
```

**Другой клиент** запускает `KompasMcp.exe` без аргументов и обменивается
с ним сообщениями JSON-RPC 2.0 через stdin/stdout — по одному сообщению
в строке, в UTF-8.

### 3.3 Как ставить задачу

Задача ставится модели обычным языком. Хорошая постановка содержит:
- **что** построить и **какой документ** нужен (чертёж, модель, сборка);
- **размеры** и стандарты (модуль, число зубьев, диаметр проволоки, номинал
  крепежа, формат листа);
- **оформление**: обозначение и наименование для штампа, материал,
  технические требования;
- **куда** сохранить, если не в папку по умолчанию.

Примеры:
- «Нарисуй чертёж фланца Ø100 с центральной ступицей Ø45 и шестью
  отверстиями Ø8 на окружности Ø70, лист А3, обозначение ФЛ.001»;
- «Сделай втулку Ø60×40 с отверстием Ø30 из стали 45 и скажи массу»;
- «Построй колесо m=2, z=40, шириной 20, отверстие Ø20, и выпусти его
  чертёж»;
- «Рассчитай посадку H7/p6 для Ø30»;
- «Сделай пружину сжатия: проволока Ø2, средний диаметр 14, 10 рабочих
  витков; проверь при F1=40 Н и F2=120 Н и выпусти чертёж с диаграммой».

Модель сама выбирает инструменты и порядок вызовов. Каждый инструмент
возвращает результат (пути файлов, массу, расчётные величины, предупреждения),
и модель пересказывает его. Если инструмент сообщил об ошибке, модель видит
её текст (раздел 4) и, как правило, исправляет параметры и повторяет вызов.

**Результаты** сохраняются в папку `mcp-out` рядом с `KompasMcp.exe`:
чертежи `.cdw`, детали `.m3d`, сборки `.a3d`, рендер `.png`, `.dxf`.
Для проверки удобно просить PNG: инструменты чертежей принимают параметр
`png`, а модель может показать картинку.

### 3.4 Экземпляр КОМПАСа

Сервер работает в одном из двух режимов.

**Собственный экземпляр** (по умолчанию). При первом обращении к КОМПАСу
сервер запускает свой процесс KOMPAS.Exe со скрытым окном и работает только
с ним; уже открытые пользователем КОМПАСы не затрагиваются. Инструменты:

| Инструмент | Действие |
|---|---|
| `kompas_start` | запустить экземпляр; `visible=true` — с окном |
| `kompas_show` | показать или скрыть окно экземпляра |
| `kompas_status` | режим, PID, видимость, открытые документы |
| `list_open_documents` | открытые документы с путями |
| `kompas_stop` | закрыть экземпляр (несохранённое теряется) |

Чтобы смотреть за построением, попросите модель показать окно КОМПАСа
(`kompas_show`). Когда MCP-клиент завершает сервер, скрытый экземпляр
закрывается вместе с ним; показанное окно остаётся открытым, и с ним можно
работать как с обычным КОМПАСом.

**Режим attach** (ключ `--attach`). Сервер подключается к КОМПАСу
пользователя, в котором загружена библиотека «Давинчи» (раздел 3.10), а если
её нет — к любому запущенному КОМПАСу. Документы создаются на экране
пользователя. Запуск, показ и закрытие КОМПАСа в этом режиме запрещены:
`kompas_stop` только отсоединяет сервер. Если КОМПАС закрыли, ближайший вызов
сообщит об этом, а после повторного запуска КОМПАСа подключение
восстановится само.

### 3.5 Чертежи

Чертёж строится в активном документе: `create_drawing` создаёт лист
(форматы А0–А4, по умолчанию А3 альбомный) с рамкой и основной надписью
формы 1; дальнейшие 2D-инструменты рисуют в нём.

**Координаты.** `create_view` создаёт вид с началом в точке листа (x, y) и
масштабом; координаты геометрии задаются в миллиметрах модели относительно
начала вида. Без вида координаты — миллиметры листа от его левого нижнего
угла. Типы линий: 1 — основная, 2 — тонкая, 3 — осевая.

**Типичный порядок:**
1. `create_drawing` — лист, путь сохранения;
2. `create_view` — вид, масштаб по ГОСТ 2.302;
3. `line`, `circle`, `arc`, `polyline`, `circle_array` — геометрия;
4. `hatch` — штриховка по замкнутому контуру;
5. `lin_dim`, `diam_dim`, `rad_dim`, `ang_dim`, `dim_group` — размеры;
   `cut_line` — линия разреза; `rough` — шероховатость; `text` — надписи;
6. `tech_demands` — технические требования; `fill_stamp` — основная
   надпись (наименование, обозначение, материал, масштаб, разработчик);
7. `save_document`, `render_png`, `export_dxf`; `close_drawing`.

**Готовые чертежи деталей передач** создаются одним вызовом —
`gear_drawing`, `bevel_gear_drawing`, `worm_drawing`, `worm_wheel_drawing`,
`spring_drawing`. Они выбирают масштаб из ряда ГОСТ 2.302 так, чтобы
изображение с размерами поместилось левее таблицы и выше штампа, рисуют
таблицу параметров в правом верхнем углу, технические требования под ней и
заполняют штамп. Обозначение, наименование, материал и технические
требования передаются параметрами (`designation`, `name`, `material`,
`tech`). Если требования не поместились над штампом, результат содержит
предупреждение `warning`.

### 3.6 3D-детали и сборки

**Деталь:**
1. `create_part` — новая деталь (наименование, обозначение, путь `.m3d`);
2. `sketch` — эскиз на плоскости XOY, XOZ или YOZ, при необходимости со
   смещением `offset`; элементы — отрезки, окружности, дуги;
3. `extrude_boss` / `extrude_cut` / `revolve_boss` / `revolve_cut` —
   операции по эскизу (по умолчанию — по последнему); `hole` — сквозное
   отверстие одной командой;
4. `fillet`, `chamfer` — скругления и фаски; ребро указывается точкой на
   нём (x, y, z);
5. `set_material` — материал и плотность (`material_lookup` подскажет);
   `mass_properties` — масса и габариты;
6. `save_part`, `render_png_3d` (аксонометрия или вид `top`, `front`,
   `left` и др.), `close_part`.

Операции проверяют результат по изменению массы: если выдавливание ничего
не добавило, а вырез ничего не удалил, инструмент сообщает об этом, а не
молча оставляет модель прежней.

**Сборка:** `create_assembly` → `assembly_add_component` (файл `.m3d` или
`.a3d`) → `assembly_place` (положение и поворот вокруг оси Z по имени или
номеру компонента) → `assembly_components` (список с именами) →
`save_part`.

### 3.7 Передачи, пружины, крепёж

| Задача | Инструменты |
|---|---|
| Геометрия цилиндрической передачи | `gear_calc` |
| 3D-колесо с эвольвентным профилем, пара в зацеплении | `gear_wheel`, `gear_pair` |
| Червяк, червячное колесо, червячная пара (3D) | `worm_shaft`, `worm_wheel`, `worm_pair` |
| Коническое колесо, коническая пара (3D) | `bevel_gear_wheel`, `bevel_pair` |
| Расчёт пружины | `spring_calc` |
| 3D-пружина сжатия или растяжения | `spring_create` (`kind`: `compression`, `extension`) |
| Крепёж и подшипники | `std_part` (`kind`: `bolt`, `nut`, `washer`, `stud`, `pin`, `cpin`, `bearing`) |

Инструменты пар создают модели обоих колёс, сборку и расставляют колёса
по межосевому расстоянию с правильной фазой зацепления. Сборки пар
ссылаются на файлы колёс — не перемещайте их по отдельности.

Пружина сжатия строится с поджатыми опорными витками и сошлифованными
торцами, её высота в свободном состоянии совпадает с чертежом
`spring_drawing`. Пружина растяжения — с зацепами.

Крепёж: болты, гайки и шайбы М6–М48; шпильки, цилиндрические и конические
штифты — по диаметру и длине; шарикоподшипники 201–215 и 305–314.

### 3.8 Проверочные расчёты

`gear_check` (прямозубая цилиндрическая передача, ГОСТ 21354),
`worm_check` (червячная передача), `spring_check` (пружина сжатия,
ГОСТ 13765) работают без КОМПАСа. Результат содержит:
- `verdict` — «условия прочности выполнены» или перечень нарушенных условий;
- расчётные и допускаемые величины;
- `tech` — готовые строки технических требований.

Строки `tech` передаются в одноимённый параметр чертежа детали, например
в `worm_wheel_drawing`. `spring_drawing` при заданных силах F1 и F2 сам
рисует диаграмму испытаний и добавляет требования.

### 3.9 Сборочный чертёж и спецификация

`assembly_drawing` строит по файлу сборки `.a3d` сборочный чертёж на листе
А3: главный вид («спереди»), вид сверху под ним и, по запросу, вид слева
справа от главного; габаритные размеры; позиции линиями-выносками
(одинаковые детали — одна позиция); технические требования; штамп с
обозначением «…СБ». Параметр `spec` (по умолчанию включён) сразу выпускает
спецификацию с тем же списком позиций.

Отдельно спецификация строится `spec_drawing` по списку записей с разделами
«Документация», «Сборочные единицы», «Детали», «Стандартные изделия»,
«Прочие изделия», «Материалы». Позиции нумеруются сквозь разделы.

Выноски размещаются по габаритам компонентов — на плотных сборках
проверьте, что точка каждой выноски попала на свою деталь.

### 3.10 Копилот «Давинчи»

Копилот — окно чата прямо в КОМПАСе: запрос выполняется в открытом
КОМПАСе пользователя, документы появляются на экране.

**Подключение (один раз).** В КОМПАСе откройте менеджер приложений и
добавьте файл `davinci\DavinciNative.rtw` из папки программы. КОМПАС
запоминает список приложений — при следующих запусках меню «Давинчи»
появится само.

**Меню «Давинчи»:**
- **Панель** — открыть окно чата. Окно одно: повторный выбор пункта выводит
  его на передний план.
- **Диагностика** — имя, под которым КОМПАС зарегистрирован для сервера,
  и путь к журналу библиотеки.

**Окно чата:**

| Элемент | Действие |
|---|---|
| Строка «КОМПАС» в шапке | подключён ли КОМПАС (зелёная точка) и сколько открыто документов |
| Строка «Claude» в шапке | готова ли нейросеть: найден ли Claude Code, отвечает ли API, какая модель; при сбое — причина красным («лимит исчерпан», «нет связи — запустите Ollama» и т. п.), подробности — во всплывающей подсказке. Щелчок — проверить ещё раз |
| Кнопка «Новый диалог» (карандаш) | очистить ленту и начать разговор заново |
| Кнопка «Настройки» (ползунки) | страница настроек (ниже) |
| Полоса под шапкой | бежит, пока Давинчи работает над запросом |
| Примеры на пустом экране | щелчок подставляет пример в поле ввода |
| Поле ввода | Enter — отправить, Shift+Enter — новая строка |
| Скрепка | приложить файлы (эскиз, ТЗ, модель); файлы можно и перетащить в окно. Вложения видны над полем ввода, крестик убирает лишнее; копии кладутся в `<рабочая папка>\attach` |
| Круглая кнопка справа | отправить; пока идёт запрос — остановить его |

Лента: ваш запрос — справа, ответ Давинчи — слева, с оформлением (списки,
таблицы, код). Пути к файлам в ответе — ссылки: щелчок открывает файл. Под
ответом — строка хода: во время работы «Выполняю: create_part», после —
«Шагов: 6 · 41 с»; щелчок по ней раскрывает список инструментов, неудачные
отмечены «— ошибка». Текст ответа можно выделять и копировать.

Диалог непрерывный: следующее сообщение продолжает предыдущий разговор, пока
не нажата кнопка «Новый диалог». Окно ведёт себя как обычное и перекрывается
другими окнами; закрепить его поверх можно в настройках. Если Claude заведомо
недоступен (нет Claude Code, нет связи с API), запрос не отправляется — панель
пишет причину, текст остаётся в поле ввода.

**Страница настроек** (кнопка с ползунками). Изменения применяются кнопкой
«Сохранить» со следующего запроса; «Отмена» и стрелка «назад» ничего не меняют.

| Раздел | Параметры |
|---|---|
| Нейросеть | Источник: **Claude Code** — ваш вход, как `claude` в терминале; **Ollama** — сервер Ollama на компьютере (адрес, по умолчанию `http://127.0.0.1:11434`); **Другой API** — Anthropic-совместимый API (адрес и ключ). Модель: имя или вариант из подсказок (для Claude Code — sonnet, opus, haiku; для Ollama — модели с сервера). «Проверить» — пробный запрос с введёнными параметрами |
| Работа | рабочая папка (файлы модели и вложения), лимит времени на запрос в минутах, команда запуска Claude Code |
| Окно | тема (как в Windows, светлая, тёмная); «Поверх других окон» |

**Вход.** Для источника «Claude Code» отдельный вход не нужен: если
`claude -p "привет"` отвечает в обычном терминале пользователя, копилот тоже
работает. Переменные окружения пользователя (прокси, ключи) панель берёт из
реестра; дополнительные можно задать в `davinci.json` (раздел `env`).

**Файл настроек** — `davinci\davinci.json` (страница настроек пишет в него же;
прочие ключи файла сохраняются):

| Ключ | Назначение | По умолчанию |
|---|---|---|
| `provider` | источник: `claude`, `ollama`, `api` | по `env`: есть `ANTHROPIC_BASE_URL` — Ollama или API, иначе Claude Code |
| `baseUrl`, `apiKey` | адрес и ключ для Ollama и другого API | Ollama: `http://127.0.0.1:11434`, ключ `ollama` |
| `model` | модель (передаётся claude явно) | модель Claude Code по умолчанию |
| `kompasMcpExe` | путь к серверу | `KompasMcp.exe` уровнем выше библиотеки |
| `workspace` | рабочая папка модели и вложений | `mcp-out` рядом с сервером |
| `claudeCmd` | команда запуска Claude Code | `claude.cmd` |
| `timeoutSec` | лимит времени на запрос, с | 900 |
| `env` | дополнительные переменные окружения (поверх источника) | — |

Тема, закрепление, размер и положение окна хранятся в
`HKCU\Software\KompasMcp\Davinci`.

### 3.11 Сценарии без MCP-клиента

Сервер можно прогнать по готовому сценарию — последовательности вызовов
инструментов в файле `.jsonl` (формат — приложение В). Из папки программы:
```
powershell -ExecutionPolicy Bypass -File examples\run_smoke.ps1 examples\smoke_gears3d.jsonl
```
Скрипт печатает по строке на каждый вызов: номер, признак ошибки
`isError` и ответ. Сценарии из `examples` — рабочие рецепты построения
деталей, передач, пружин, сборок; их перечень — в README.

Вызывать сервер обычным конвейером PowerShell (`Get-Content … |
KompasMcp.exe`) нельзя: конвейер перекодирует кириллицу, и в документах
вместо букв окажутся вопросительные знаки. `run_smoke.ps1` пишет UTF-8
напрямую.

### 3.12 Завершение работы

Сервер завершается, когда MCP-клиент закрывает его поток ввода (выход из
Claude Code, закрытие Claude Desktop). Скрытый экземпляр КОМПАСа при этом
закрывается, несохранённые в нём документы теряются — инструменты,
создающие файлы, сохраняют их сами, а документы, построенные по шагам,
сохраняет `save_document` или `save_part`. Если окно экземпляра было
показано, КОМПАС остаётся открытым.

Если сервер завершился аварийно, скрытый КОМПАС может остаться в памяти:
он виден в диспетчере задач как KOMPAS.Exe без окна, его можно завершить там.

Панель «Давинчи» закрывается крестиком; выполняющийся запрос при этом
останавливается. КОМПАС пользователя панель не закрывает.

## 4. Сообщения оператору

Сообщения об ошибках инструментов получает модель; обычно она исправляет
вызов сама. Если ошибка повторяется, ниже — что она означает.

| Сообщение (начало) | Причина | Действие |
|---|---|---|
| `Отсутствует обязательный … аргумент '…'`, `Аргумент '…' не число` | модель не передала параметр или передала его в неверном виде | уточнить запрос: указать недостающий размер |
| `Нет активного чертежа — вызовите create_drawing` | 2D-инструмент вызван без открытого чертежа | начать с создания чертежа |
| `Нет открытой детали — вызовите create_part или open_part` | 3D-инструмент вызван без детали | начать с создания или открытия детали |
| `Нет эскизов — вызовите sketch`, `Нет эскиза с id=…` | операция без эскиза | создать эскиз |
| `выдавливание ничего не добавило …`, `вырез ничего не удалил …` | эскиз совпадает с телом или лежит вне его | проверить положение эскиза и сторону операции |
| `Ни одного ребра не выбрано по точкам` | точка для фаски или скругления не лежит на ребре | указать точку ровно на ребре |
| `Нет номинала М…`, `Нет кода …` | такого крепежа или подшипника нет в таблицах | выбрать номинал из раздела 3.7 |
| `Материал не найден: …` | материала нет в справочнике | задать название и плотность явно (`set_material`) |
| `Нужны m > 0 и целые z >= 6`, `Ширина венца …`, `Нужен bore …` | недопустимые параметры передачи | исправить модуль, число зубьев, ширину, отверстие |
| `Файл компонента не найден`, `Нет файла сборки` | неверный путь | проверить путь; в путях допустимы абсолютные и относительно папки сервера |
| `КОМПАС не сохранил файл` | папка недоступна для записи или файл открыт в другом КОМПАСе | сохранить в другую папку, закрыть файл |
| `КОМПАС закрыт или недоступен (RPC не отвечает)` | КОМПАС закрыли или он аварийно завершился | запустить КОМПАС и повторить — сервер переподключится |
| `attach: КОМПАС не найден в ROT …` | режим attach, а КОМПАС не запущен | запустить КОМПАС с библиотекой «Давинчи» |
| `attach-режим: … запрещён` | в режиме attach нельзя запускать, показывать и закрывать КОМПАС | — (так задумано) |
| `Activator.CreateInstance вернул null …`, код `0x80040154` | COM-классы КОМПАСа не зарегистрированы | один раз запустить КОМПАС вручную |
| `Неизвестный tool: …` | клиент вызвал инструмент, которого нет в этой версии | обновить сервер или клиента |

Предупреждения в результате (`warning`, `warning_undercut`) не прерывают
работу: документ построен, но его стоит проверить — например, технические
требования не поместились над штампом, или у колеса с малым числом зубьев
подрезается ножка.

Подробности каждого вызова и все ошибки пишутся в журнал
`kompas-mcp.log` рядом с `KompasMcp.exe` (туда же пишет панель «Давинчи»).
Журнал самой библиотеки «Давинчи», загруженной в КОМПАС, —
в `%TEMP%\kompas-davinci\`.

## Приложение В. Формат сценария

Сценарий — текстовый файл в UTF-8, одна строка — одно сообщение JSON-RPC.
Первым идёт `initialize`, затем вызовы инструментов `tools/call`:

```
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05"}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"create_part","arguments":{"name":"Втулка","path":"mcp-out\\bush.m3d"}}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"sketch","arguments":{"plane":"XOY","elements":[{"type":"circle","xc":0,"yc":0,"r":30}]}}}
{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"extrude_boss","arguments":{"depth":40,"base":true}}}
{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"hole","arguments":{"xc":0,"yc":0,"r":15}}}
{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"set_material","arguments":{"name":"Сталь 45 ГОСТ 1050-88","density":7850}}}
{"jsonrpc":"2.0","id":7,"method":"tools/call","params":{"name":"mass_properties","arguments":{}}}
{"jsonrpc":"2.0","id":8,"method":"tools/call","params":{"name":"save_part","arguments":{}}}
```

Относительные пути в аргументах (`mcp-out\\bush.m3d`) считаются от папки
`KompasMcp.exe`.

Ответ на вызов инструмента — объект `result` с полем `content` (текст —
JSON результата инструмента) и признаком `isError`. Ошибка протокола
(неизвестный метод, неразборчивая строка) — объект `error` с кодом.
